# 安全策略

## 最重要的警告：不可信的作弊表会执行代码

本工具会检查并修改其他进程的内存，通常以较高权限运行（`ptrace`，往往配合 `sudo`），而且它的作弊表格式是可编程的。

**不要打开来源不可信的 `.CT` / `.CETRAINER` 文件。** 作弊表里可以内嵌会自动运行的 Lua。打开恶意表可能在你机器上执行任意代码，权限通常就是你启动本工具时所用的权限（也就是说，如果你用了 `sudo`，那就是 root）。请把别人分享的表当作别人分享的可执行文件来对待。

Lua 接口中最危险的两部分**默认被禁用**，只能通过表自身脚本无法设置的带外开关启用，即在启动进程时设置环境变量 `CECORE_LUA_ALLOW_UNSAFE=1`：

- `shellExecute` — 执行任意 shell 命令。
- `write*Local` 系列函数 — 写入 cecore *自身*的地址空间，恶意表可用它给 cecore 的代码/GOT 打补丁从而劫持进程。

`read*Local` 系列函数（读取宿主内存 / 信息泄露）以及其余针对目标进程内存的 API 仍然可用，所以操作准则依旧成立：只加载你自己编写或信任的表。此外，所有原生绑定都统一经过一个异常防火墙，因此从绑定中逃逸的 C++ 异常会变成 Lua 错误，而不会穿过 liblua 的 C 栈帧向上展开。

## 以最小权限运行

- 在目标允许的情况下，优先以普通用户运行并适当设置 `/proc/sys/kernel/yama/ptrace_scope`，或使用 `PR_SET_PTRACER`，而不是一律 `sudo`。
- 可选的内核模块（`kernel/cecore_kmod.ko`）会暴露一个特权内存访问设备；只在需要时加载，用完后卸载。

## 支持的版本

只有最新发行版和 `main` 分支会获得修复。这是 1.0 之前的软件。

## 上报漏洞

请私下上报安全问题，不要开公开 issue：在仓库中提交 GitHub **Security Advisory**（`Security → Report a vulnerability`），或发邮件给维护者。请附上问题描述、受影响的版本/提交，以及尽可能提供复现步骤。我们会在几天内确认收到。
